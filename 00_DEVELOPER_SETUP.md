> **For**: The AIDa developer.
> **Time**: 30–60 minutes from "fresh laptop" to "Claude Code running in repo".
> **Read this end-to-end before typing anything.** Then come back and execute it step by step.

## 1. Prerequisites

### 1.1 Operating system
- **macOS 13+** ✅ (recommended)
- **Linux Ubuntu 20.04+ / Debian 10+** ✅
- **Windows 10/11**: install via WSL2 (Ubuntu). Native PowerShell works but has rough edges. **Use WSL2.**

### 1.2 Tools you need

| Tool | Min version | Why |
|---|---|---|
| Node.js | 20+ | Next.js 15 needs Node 18.18+; we use 20 LTS |
| pnpm | 9+ | Faster, less disk than npm; we standardize on it |
| Git | 2.40+ | Version control |
| GitHub account | — | For pushing the repo |
| A modern terminal | — | iTerm2, Warp, Windows Terminal, or default macOS Terminal |
| VS Code (or Cursor) | — | For editing files; Claude Code does the writing |
| Claude Pro/Max subscription OR API key | — | Claude Code needs this |

### 1.3 Install Node.js (skip if you already have 20+)

**macOS / Linux** (use nvm — never use sudo with npm):
```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.0/install.sh | bash
# restart terminal
nvm install 20
nvm use 20
nvm alias default 20
node --version  # should print v20.x.x
```

**Windows (WSL2)**: same as Linux above, run inside WSL.

### 1.4 Install pnpm
```bash
npm install -g pnpm
pnpm --version  # 9 or higher
```

### 1.5 Configure Git (if not already)
```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

## 2. Install Claude Code

### 2.1 Native installer (recommended)
**macOS / Linux:**
```bash
curl -fsSL https://claude.ai/install.sh | bash
```

**Windows PowerShell** (run as regular user, NOT admin):
```powershell
irm https://claude.ai/install.ps1 | iex
```

Close and reopen your terminal so PATH updates.

### 2.2 Verify
```bash
claude --version
```
You should see a version number. If "command not found", reopen your terminal. Still nothing? See troubleshooting at the bottom.

### 2.3 Authenticate
```bash
claude
```
First run opens your browser. Sign in with your Anthropic account (the one that has Pro/Max). Approve. Come back to the terminal.

> **If you're using an API key instead of a subscription**, set `ANTHROPIC_API_KEY` in your shell profile (`~/.zshrc` or `~/.bashrc`):
> ```bash
> export ANTHROPIC_API_KEY="sk-ant-..."
> ```
> Then `source ~/.zshrc` and run `claude` again.

### 2.4 Sanity check
```bash
claude doctor
```
This runs a health check. Fix anything red before proceeding.

## 5. Configure Claude Code for the repo

### 5.1 Optional but recommended — set the model

Claude Code defaults are usually fine. You can override per-command:
```bash
claude --model claude-opus-4-7      # smartest, slowest, more tokens
claude --model claude-sonnet-4-6    # balanced — recommended default
claude --model claude-haiku-4-5     # fastest, cheapest, for simple edits
```

For AIDa, **Sonnet is the sweet spot.** Use Opus when you're stuck on a hard architecture decision; use Haiku for quick mechanical edits.

### 5.2 Confirm CLAUDE.md is in place
```bash
cat CLAUDE.md | head -20
```
Should show the AIDa project header. This file is loaded automatically every Claude Code session — it's how Claude knows the project.

### 5.3 Run the first session
```bash
cd ~/code/aida
claude
```

You'll see a `>` prompt. **Don't type anything custom yet.** Type:
```
Read CLAUDE.md, README.md, and docs/dev/DEVELOPER_GUIDE.md. Summarize the project, the locked tech stack, and the next 3 things we need to build, in under 200 words.
```

This is your sanity check. If Claude Code summarizes correctly, you're ready. If it hallucinates or asks for files it shouldn't need, something's off — re-check the docs are in the repo root.

Type `/exit` to leave. We'll come back with real prompts.

## 6. Daily workflow — how to use Claude Code

### 6.1 Starting a session
```bash
cd ~/code/aida
git pull            # if working with someone else
git checkout -b feat/<feature-name>
claude
```

### 6.2 The "Explore → Plan → Implement → Commit" loop
This is the workflow that keeps Claude Code from going off the rails. **Use it for every feature.**

1. **Explore**: ask Claude to read the relevant files first.
   ```
   Read CLAUDE.md, app/onboarding/page.tsx, and lib/db/schema.ts. Don't write anything yet.
   ```

2. **Plan**: ask for an approach before code.
   ```
   Now propose a plan for adding a multi-step wizard to onboarding. Don't write code. Just outline the file changes you'd make and why.
   ```
   You read it, push back, agree.

3. **Implement**: now let it write.
   ```
   Implement the plan. Stop after each file and let me confirm before moving to the next.
   ```

4. **Commit**: review with `git diff`, then commit.
   ```
   git add -p && git commit -m "feat: onboarding multi-step wizard"
   ```

### 6.3 Plan mode (built-in)
Claude Code has a `/plan` mode that forces planning before editing:
```
/plan
```
It then proposes changes and waits for your approval before touching files. **Use this for anything non-trivial.** Hit `Esc` to exit plan mode.

### 6.4 Slash commands you'll actually use

| Command | What it does |
|---|---|
| `/init` | Auto-generate a CLAUDE.md (we already have one — don't run unless you want to merge in suggestions) |
| `/plan` | Plan mode — propose, then implement after approval |
| `/clear` | Clear the conversation context (use between major tasks to avoid context bloat) |
| `/compact` | Summarize the long conversation to save context tokens |
| `/cost` | Show token spend for the session |
| `/exit` or `Ctrl+D` | Leave the session |

### 6.5 When to start a new session
**Always start a new session for a new feature.** Long sessions accumulate context noise and Claude starts confusing parts of unrelated tasks. Hit `/clear` between features OR just `/exit` and re-launch.

### 6.6 Permissions
By default Claude Code asks before running commands or editing files. **Leave this on for the hackathon.** A wrong autonomous action can cost you an hour of debugging.

If you want it more autonomous on a contained task, use:
```bash
claude --dangerously-skip-permissions
```
But only for a known-safe task and only in a session where you'll watch the output.

### 6.7 Stop generations gone wrong
`Esc` cancels the current generation. `Ctrl+C` is harder — it can leave the terminal in a weird state. Prefer `Esc`.

## 7. How the prompt files in this folder work

The `prompts/` folder contains **numbered prompt files**. Each one is a single copy-paste-into-Claude-Code prompt that builds one chunk of the app.

**Run them in order.** Don't skip. Each prompt assumes the previous one ran successfully.

```
prompts/
  01_repo_bootstrap.md          ← Block A: skeleton, dependencies, config
  02_database_schema.md          ← Drizzle schema + Supabase migration
  03_auth_phone_otp.md           ← Phone OTP login + useUser hook
  04_app_shell.md                ← Bottom-tab nav, PWA manifest, theme
  05_i18n_setup.md               ← next-intl with EN + BM
  06_onboarding_wizard.md        ← 6-step onboarding flow
  07_seed_aid_catalog.md         ← Load BAs' aids.json into DB
  08_aids_browse.md              ← Aids list + detail pages
  09_bedrock_client.md           ← AWS Bedrock helper, prompt files
  10_matching_engine.md          ← Rule pre-filter + Claude reasoning
  11_home_screen.md              ← Match results + "near miss" UI
  12_aida_chatbot.md             ← Streaming chat, multilingual, suggested replies
  13_tracker.md                  ← Applied / eligible / renewals
  14_ocr_mykad.md                ← Textract + autofill
  15_insights_dashboard.md       ← Quick BI iframe + admin page
  16_polish_and_translations.md  ← ZH + TA, loading states, empty states
  17_deploy_to_vercel.md         ← Production deployment
  18_demo_seed.md                ← Mak Cik Aminah demo account
```

### How to run one
1. Open the file (e.g. `prompts/01_repo_bootstrap.md`).
2. Read the **"Pre-flight check"** section — make sure prerequisites are met.
3. Copy the **prompt block** (the part inside the big code fence).
4. Start Claude Code in the repo: `cd ~/code/aida && claude`.
5. Paste the prompt. Hit Enter.
6. **Use `/plan` mode** if it's a complex prompt (the file will tell you when).
7. Review changes file-by-file. Approve.
8. Run the **"Verification"** commands at the bottom of the prompt file.
9. Commit with the suggested commit message.
10. `/exit`. Move on to the next prompt.

### What if a prompt fails or produces garbage?
- Don't try to fix it inside the same Claude Code session — it's confused.
- `git reset --hard HEAD` to wipe uncommitted changes.
- `/exit`, start a fresh session.
- Re-paste the prompt with the failure note appended:
  ```
  [PROMPT TEXT]

  Note: a previous attempt at this failed because <reason>. Avoid that path.
  ```

## 8. The "small commits" rule

Commit after **every working prompt file**, not at the end. Aim for **15–25 commits across the hackathon.** Tiny commits = easy rollbacks = sanity.

Commit message format:
```
<type>: <short message>
```
where `<type>` is one of: `feat`, `fix`, `chore`, `docs`, `refactor`, `style`, `test`.

Examples:
```
feat: phone OTP auth flow
fix: onboarding step 3 validation
chore: bump shadcn components
docs: add demo day runbook
```

## 9. Troubleshooting

### `claude: command not found`
- Close and reopen your terminal.
- Check PATH: `echo $PATH | tr ':' '\n' | grep claude`.
- Native installer puts it in `~/.local/bin/claude` (Linux/macOS). Add `export PATH="$HOME/.local/bin:$PATH"` to your shell profile if missing.

### Authentication loop
- Run `claude logout` then `claude` to re-auth.
- Make sure your subscription is active.

### `EACCES` permission errors during npm install
- Don't use `sudo`. Switch to nvm (see §1.3).

### Bedrock returns 403 inside the app
- DevOps has not granted model access yet. Bug DevOps.

### Supabase OTP not arriving
- Twilio needs to be configured in Supabase auth settings, OR use email OTP for local dev.
- For demo, we'll use a magic-login bypass for the Mak Cik Aminah account (see prompt 18).

### Claude Code keeps suggesting Prisma / Express / Redis
- Your CLAUDE.md isn't being read. Verify with `claude` then ask:
  ```
  What ORM and what backend framework are we using? Quote the source file.
  ```
  It should cite CLAUDE.md and say "Drizzle, Next.js Route Handlers."

### Out of context / Claude is "forgetting" things mid-session
- Run `/compact` to summarize.
- Or `/clear` and restart from a fresh prompt.

### A prompt file produces 800 lines of code that doesn't compile
- That's a sign the prompt was too big OR Claude got confused.
- Roll back: `git reset --hard HEAD`.
- Break the prompt into 2–3 smaller asks.

## 10. Performance, cost, and pacing

- Watch your token spend with `/cost` periodically. Hackathon-wise we're well under any limit, but no need to be wasteful.
- Sessions over 100k tokens of context get sluggish. `/compact` or `/clear` to refresh.
- If a prompt has been running > 90 seconds, hit `Esc`, simplify the ask.

---

## 11. The two killer habits

1. **`/plan` first, code second.** Even when you're sure. The 30 seconds of planning saves 20 minutes of unwinding.
2. **One feature, one branch, one PR-style commit.** Never commit a half-built feature on top of a half-built feature. If the demo needs a rollback, you'll thank yourself.
